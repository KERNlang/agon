**Position: FOR acceptance of the corrected plan — with executable gates, not structural redesign.**

The single strongest piece of evidence for this plan is its own correction history. A false green survives only in systems that cannot falsify themselves. This plan already did: a prior green receipt was *superseded* the moment three independent defects surfaced — staged compilation failing without ignored declarations, hashes computed over ambient files, and 4 duplicate edges hiding inside 148 declared dependency entries. That is not a plan that got lucky; that is a plan whose evidence model can detect its own lies. The corrected plan (49 packages, 144 unique edges, 852 source assignments, topological order) is internally checkable arithmetic: 148 declared minus 4 duplicates equals 144 unique. A false green requires numbers that don't reconcile. These reconcile.

**On evidence quality.** The adversary's core attack is "source-free means unverifiable." Wrong on the facts. Verifiability doesn't require source access; it requires (a) machine-checkable invariants, (b) a non-self-referential ground truth, and (c) gates that fail loudly. The original false green came from self-reference: the manifest hashed ambient files, so the manifest validated itself against noise. S1B breaks that loop two ways. First, clean staged compilation *without ignores* as an exit criterion eliminates the exact mechanism that produced the prior false green — ignored declarations were the hiding place, and the corrected plan dynamites it. Second, the frozen legacy oracle gives every later slice ground truth that is not derived from the new implementation. The 852 legacy source assignments guarantee each file has exactly one home, which is the precondition for "compile slice N in isolation" to even be a meaningful sentence. This repo also has the tooling to make gates real today: the `tests/` tree already splits unit/spec/integration under vitest, so per-slice entry/exit commands are executable `npm run test:ts` scopes, not aspirations. And the culture is demonstrably anti-false-green: recent commits are literally "kill 23 mutation survivors — targeted assertions for untested guards" and "honest editor-launch reporting."

**On ordering.** The predictable attack: "S7 transactional install is too late; security (S8) gates nothing." Both get the epistemics backwards. Testing an installer before S5/S6 freeze the artifact set means testing against stubs — the classic false-green generator: the installer "passes" because there's nothing real to corrupt. Same for trust: a trust layer in S1 would be validated against zero mods and zero surfaces. S8 lands *after* 36 mods and the disable matrix exist, so grants and folder mods are tested against real capability surfaces. Meanwhile, failure-path I/O testing is *not* deferred: S7 already mandates concurrent-writer, ENOSPC, EACCES, and torn-write tests plus third-party fail-closed — that's the security-relevant filesystem behavior, adversarially tested, before S8's semantic layer. And S4's N-1/N-2 compatibility requirement is the guard that makes sequencing itself safe: without it, slice 6 could silently regress slice 3. Topological order from the deduplicated edge set isn't stylistic; it's the only order in which isolated compilation is definable.

**On rollback.** "Every slice has rollback commands" will be dismissed as decorative unless executed. Fair — but that's a one-line gate addition, not a design flaw. The design is the hard part, and the design is right: S2's crash-safe *immutable-generation* host makes rollback a pointer flip rather than a file-rewrite, which is what makes rollback *testable* for torn states at all. Compare with the in-repo precedent: "harden call and upgrade workflow contracts" and `docs/upgrade-pressure-test.md` show this org already pressure-tests exactly this failure class. Local fix: require exit gate = exit command passes AND rollback executes AND re-entry passes, with failure receipts in the shape of `buildAskFailureDetail` (headline + truncated stderr, as in `packages/cli/src/commands/ask.ts`) so red gates are legible, not just red.

**On packaging.** S7 tests the four failure modes that actually break real global installs: concurrent writers, ENOSPC, EACCES, torn writes. And the discipline it requires is already landing: the diff narrows `packages/cli/package.json` `files` from the ambient `py/` glob to two explicitly enumerated probes. That is the same fix pattern that killed the hash-over-ambient-files defect — explicit manifests, never ambient capture. The plan and the codebase are converging on the same invariant.

**On cross-platform.** S9 covers npm/npx plus native macOS/Linux plus historical state migration. Windows absence is not a gap against the plan's own acceptance contract — it's out of declared scope. Migration correctly sits last because migration tests need the final schema frozen; migrating mid-stream guarantees re-migration bugs.

**What I concede — all locally actionable, none structural:**

1. **P0 — Oracle capture boundary must be pinned at the raw-output persistence layer, pre-cleaning.** The docstring on `stripReasoning` in `packages/cli/src/blocks/engine-helpers.ts` says to apply it "wherever raw engine output is persisted or parsed." If the frozen oracle is captured *after* `cleanVisibleEngineOutput` / `stripReasoning` / `stripTuiChrome`, a cleaning bug (say, the newly added Ollama `Thinking... done thinking.` stripper matching too aggressively) becomes baked into ground truth — a false green by construction. Freeze at the raw boundary; test cleaners separately. Similarly, oracle captures must pin engine sets via the same logic as `filterDefaultOrchestrationEngines`, or filtering variance flips determinism. With 12 `engines/*.json`, a deterministic pinned subset per slice plus a full sweep at S6/S9 keeps the oracle affordable without making it a mere sample.
2. **P0 — Duplicate-edge rejection as a lint/schema gate.** The 148→144 dedup must be enforced mechanically so it can't regress to 149 with 5 dupes unnoticed.
3. **P0 — Rollback commands executed in CI, per the gate above.** Presence is not evidence; execution is.
4. **P1 — Mutation testing on the resolver/registry/manifest layer specifically.** That's the risk center of a source-free foundation, and the repo already has a survivor-killing workflow to reuse.
5. **P2 — Real macOS and Linux CI runners, not one simulating the other**, especially for EACCES on SIP-protected paths.

**True external blockers:** essentially one class. "Legacy runtime is authoritative" means oracle freshness depends on upstream engine behavior, and this repo carries `patches/@kernlang+agon-engines+0.1.3.patch` precisely because upstream drifts. If legacy ships breaking changes mid-plan, an oracle refresh is externally gated — the freeze manages but cannot eliminate that. The only other strain is hardware-dependent EACCES coverage requiring a physical macOS runner. Neither warrants redesign.

**Verdict, prioritized:** Accept the corrected plan. The supersession event proves the evidence model is falsifiable; clean staged compilation without ignores removes the prior false-green mechanism at its root; the frozen oracle, topological order, immutable-generation rollback, N-1/N-2 compatibility, and failure-path install tests form a coherent anti-false-green architecture. Condition acceptance on the three P0 local fixes (raw-boundary oracle capture with pinned engine sets, mechanical duplicate rejection, executed rollback gates) before S2 begins, P1 mutation coverage before S4, P2 dual-OS runners before S7. Everything else the adversary will raise — earlier security, earlier packaging, Windows — either tests against stubs (manufacturing false greens) or silently rewrites scope. The plan's weakness is not its structure; it's whether its gates are *executed*, and that is fully within this repo's power to fix today.
